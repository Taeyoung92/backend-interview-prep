## TCP/UDP의 정의/차이점/장단점
TCP(Transmission Control Protocol) - 연결을 먼저 맺고(connection), 데이터가 정확하고 순서대로 도착하는 것을 보장하는 신뢰성 중심 프로토콜.
UDP(User Datagram Protocol) - 연결 과정 없이, 데이터를 일단 빠르게 던지는 속도 중심 프로토콜. 도착 여부/순서를 보장하지 않음.

**차이점**

| 구분 | TCP | UDP |
|---|---|---|
| 연결 방식 | 연결형 (handshake 필요) | 비연결형 (그냥 전송) |
| 신뢰성 | 보장 (재전송으로 손실 복구) | 보장 안 함 (손실돼도 끝) |
| 순서 보장 | 보장 (순서대로 재조립) | 보장 안 함 |
| 속도 | 상대적으로 느림 | 빠름 |
| 흐름·혼잡 제어 | 있음 | 없음 |
| 헤더 크기 | 큼 (20~60 byte) | 작음 (8 byte) |
| 전송 단위 | 바이트 스트림 | 데이터그램(패킷) |

**장단점**

TCP
- 장점 : 데이터가 빠짐없이, 순서대로 도착함. 손실되면 재전송하고, 네트워크 혼잡 시 속도를 조절(흐름·혼잡 제어). 신뢰성이 생명인 통신에 적합
- 단점 : 연결 수립·확인·제어 과정 때문에 상대적으로 느리고 오버헤드가 큼

UDP
- 장점 : 연결·확인 절차가 없어 빠르고 가벼움. 실시간성이 중요한 통신에 적합. 1:다 전송(브로드캐스트·멀티캐스트)도 가능
- 단점 : 데이터가 유실·중복·순서 뒤바뀜이 생길 수 있고, 이를 막으려면 애플리케이션이 직접 처리해야 함

TCP와 UDP를 사용하는 경우
- TCP - 한 글자라도 틀리면 안되는 것 > 웹, 이메일 ,파일전송 >> 데이터가 깨지면 안 됨
- UDP - 조금 손실돼도 되지만 빨라야 하는 것 > 실시간 스트리밍, 화상통화/음성통화, 온라인 게임, DNS 조회

## 웹소켓이란?
웹소켓(WebSocket) = 한 번 연결하면, 그 연결을 계속 유지하면서 서버와 클라이언트가 양방향으로 자유롭게 데이터를 주고받는 통신 프로토콜.

핵심 특징 :
- 양방향 : 서버도 클라이언트도 먼저 말을 걸 수 있음
- 연결 지속 : 한 번 연결하면 끊지 않고 계속 사용(HTTP처럼 매번 끊지 않음)
- 가벼움 : 연결 후엔 매번 무거운 HTTP 헤더를 붙이지 않아 오버헤드가 적음

연결 방법 :
- 연결의 시작은 HTTP로 함.(Handshake)
- 처음엔 HTTP로 핸드셰이크 > 101 Switching Protocols 응답으로 프로토콜이 웹소켓으로 바뀜
- 이후엔 같은 TCP 연결을 그대로 쓰되 웹소켓 프로토콜로 통신
- 주소 체계가 http:// → ws://, https:// → wss://(암호화) 로 바뀜

*** HTTP로 시작하는 이유? : 기존 웹 인프라(포트 80/443, 방화벽, 프록시)와 호환을 위해서. 새 포트를 열지 않고 기존 HTTP 통로로 자연스럽게 연결을 시작.

## 실시간 통신 방식 4가지

1. **Polling(폴링)** - 클라이언트가 일정 주기로 계속 신규 요청
   - 단점 : 새 데이터가 없어도 계속 요청 → 불필요한 트래픽 및 서버 부하. 주기 사이에 지연도 생김

2. **Long Polling(롱 폴링)** - 요청을 보내면 서버가 데이터가 생길때까지 응답을 미룸. 응답 오면 즉시 다시 요청
   - 폴링보다 낫지만, 응답 때마다 연결을 다시 맺어야함

3. **SSE(Server-Sent Events)** - 연결을 유지하되 서버 → 클라이언트 단방향으로만 데이터를 밀어줌
   - 알림/시세처럼 받기만 하면 되는 경우 가볍고 충분함. 단, 클라이언트가 보낼 길은 없음

4. **WebSocket(웹소켓)** - 연결 유지 + 양방향. 서로 자유롭게 송수신
